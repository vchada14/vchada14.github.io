01 — A system I built and kept running

Co-op reporting system

Before

Rebuilt by hand every week

Two reports reconstructed from a spreadsheet export. About a day of work, and it only ever showed the current term.

After — the highest-value part

The semantic layer, not the dashboard

Each metric defined once in the model instead of reconstructed in a pivot table every week. Nine metrics, six cycles of history.

Try it — the same row, one week later
709 Week 1 · InternalStatus = All

Same label on the report. A completely different definition underneath. Not slow — not reproducible.

Try it — one metric, 261 filter values

Counting postings open to Khoury students

Target majors is a free-text field. Identifying the right postings meant selecting every combination containing “Khoury” — by hand, in a pivot filter, every single week.

261 values waiting. Pick a method.
Broke — 1

455,000 rows per click

A click-through to the postings behind each number filtered the entire table. It blew the memory limit and the query wouldn't run at all.

Stopped calculating at query time and precomputed the lists at refresh — same answers, instant.

Try it — drag the refresh lag

A rolling seven-day metric

The marts refresh overnight in batch. Push the last refresh far enough back and the window has nothing left to sit on.

14 days agotoday
4 Last refresh 1 day ago

A visible “as of” stamp, and a date label built from the same logic that computes the window.

The lesson

Point-in-time metrics against a batch source fail quietly

Cumulative counts survive a late refresh. Anything measuring current state does not — and it won't tell you that it hasn't.

02 — Responsible for other people's work

University-wide ELR approval workstream

Starting condition

Nine colleges, nine data managers, nobody formally leading

Every college handled experiential learning record approvals differently — that's the record created when a student accepts a co-op placement. We were all at the same level, so I took it on informally.

01

Wrote down how each college actually works

We'd all been describing our own process and assuming everyone else matched. Once documented, the differences were obvious and we stopped talking past each other.

02

Structured the sessions, then looked outward

An agenda so each manager had airtime for what they knew about their own college. And I went outside the group early, to Admin Application Development Services.

That surfaced it — no write access. Full automation was ruled out in week two, not after designing around it.

03

Now and long-term, side by side

Some wanted the full redesign, others something shippable. Two columns meant nobody's idea got thrown out — the ambitious ones became the roadmap.

Outcome

Recommendations taken forward by leadership

Being built into NUworks Staff Utilities now, deploying next semester. What was scoped out became two follow-on project groups rather than being dropped.
